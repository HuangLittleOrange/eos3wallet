# 绑定授权生命周期与设备密钥误删：复现、修复和验证

日期：2026-10-18。基于当前主工作区（含此前未提交修复）处理 Hermes r2 的两项发现。复现只使用本机生成的无资金测试密钥、内存存储及模拟 RPC/服务；没有访问真实钱包、广播交易或操作生产凭据。未打包、签名或发布新安装包。

## 1. 绑定授权的旧确认继续有效

原 `BindAuthorizeScreen` 的 `isCurrent` 仅比较挂载状态及上下文字符串。普通后台不使确认失效；账户 A→B→A 后字符串又相等，旧解锁操作仍能继续；准备授权时的异步结果也可能在同样的往返后打开旧确认。

对照测试挂载真实屏幕，暂停授权准备或解锁，注入 AppState/钱包变更，再释放 Promise。旧实现会继续调用交付适配器，或者在应已失效时仍显示确认。5 项生命周期对照均检出了该行为。服务端授权 API、系统解锁与签名适配器为模拟；测试中的交付适配器按实际领域函数的前置、解锁后检查契约执行，不声称已经完成真实链上授权。既有 `chain/__tests__/bindAuthorize.test.ts` 继续覆盖实际领域函数的计划冻结和上下文检查。

修复复用 `useSigningGuard`，把绑定 ID、链、账户、节点、钱包 ID 和公钥绑定到本次确认。普通后台立即清除确认；上下文的每次改变均使旧准备/签名代次失效，往返到相同账户也不能恢复旧尝试。确认对象引用另作核对，旧按钮不能代替新确认；手动关闭同步作废引用。对迟到结果、错误和未挂载页面不再显示旧提示。

保留 `withSystemAuthentication` 的系统认证豁免：合法生物识别/Passkey 系统流程返回前台后可以继续；普通离开应用仍取消。用户已确认的授权内容和额度没有被放宽。

## 2. 空引用列表可触发本机密钥销毁

原流程在各链返回空引用列表后，调用 `discardStoredPendingDeviceKey` 删除 pending 记录和密文。复现用真实生成的 K1 测试私钥，经实际密码派生与 AES-GCM 加密保存，再让模拟恶意所选 RPC 返回正确链 ID、空账户列表。旧函数成功返回，随后实际 vault 解密读取报 `vaultError.keyNotFound`；另一个对照也观察到原密文槽位消失。两项对照确认了误删路径，没有声称某个生产账户已因此失资。

增加多个节点仍无法证明一个密钥从未被使用：索引可能滞后，授权也可能刚发生。因此修复把操作改成“收起本机密钥”，不再依据远程负证据销毁密文：

- 先保存单独的恢复元数据，再登记恢复索引，最后清除当前 pending 槽位。全程保留原加密密钥。
- 操作与恢复按设备事务队列串行，并与秘密写入/主密码轮换互斥；写失败或原生提交后报错时，密钥仍有活动记录或可发现的恢复记录。
- 本页显示“可恢复的设备密钥”，包含名称和公钥，用户可选择恢复。恢复不会覆盖另一把活动密钥，也不会自动授予链上权限；恢复后继续使用原来的独立账户权限核验流程导入。
- 多把收起的密钥分别保留。主密码变更把这些密钥列为必须迁移的秘密，防止恢复时遇到旧密码密文。
- 六种现有语言同步修改操作说明。仍会阻止已查询到引用的密钥被直接收起，并要求先导入；查询失败也保留原记录。

该机制是本机恢复，不是云备份或链上撤权；卸载/清除本机数据的边界不变。历史版本已实际删除的密文无法由本补丁重建。
