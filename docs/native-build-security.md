# 原生构建与签名

钱包业务源码和 Expo 版本不因本流程调整。`npm run android` / `ios` 仍是原来的开发入口；这里的隔离只适用于明确调用的新入口，不自动改变 EAS 云端环境。

## Android 原生测试包

公开 GitHub Actions 构建使用同一隔离入口的 `--unsigned-only` 模式，并在另一台 runner 上独立测试签名。配置与核验说明见[公开构建与来源核验](github-android-build.md)。本机无参数入口仍执行编译和独立测试签名。

在 macOS 上安装 JDK 17，以及 `native-build-policy.json` 指定的 Android SDK 组件，并准备仅包含公开依赖的 Gradle 离线缓存：

```bash
npm run build:android:isolated
```

流程先检查依赖策略和公开源码，再创建一次性源码、用户主目录和缓存目录。npm 安装阶段可联网，但禁用安装脚本并核验来源签名；执行配置插件、测试、Prebuild 和原生编译的阶段只允许 Gradle 本地通信，不允许连接外网。沙箱拒绝读取本机用户目录、其他临时目录、常见凭据文件，拒绝修改工作区以外的文件，并拒绝钥匙串服务访问与对外部进程的检查和发送信号。只为规定的 SDK 组件和运行时工具开放必要读取。

联网准备阶段也拒绝连接临时工作区以外的 Unix 套接字，避免借 Docker 或 SSH Agent 绕过文件边界；仅为系统 DNS 解析器保留必要连接。离线编译和签名不保留这个 DNS 例外。本地 TCP 与其他系统服务仍不是虚拟机隔离边界，不能在未受控的主机上据此保证所有 IPC 渠道都安全。

优先使用本入口准备的公开依赖缓存，首次运行可从本机 `~/.gradle/caches/modules-2` 复制依赖文件和解析元数据；不复制 `gradle.properties`、初始化脚本、日志、其他 Gradle 可执行缓存或签名材料。缓存缺失时构建失败，不自动联网编译或回退到普通本机构建。

需要补充缓存时，执行 `npm run prepare:android:cache`。它在不含秘密的临时沙箱中联网执行原生配置插件和公开发行依赖解析，只保存过滤后的依赖缓存，不生成或签署 APK。缓存准备同时解析 Prefab 配置，并按构建策略预下载 AAPT2、Lint 和 Prefab CLI（含 `all` 分类器）等任务执行时才使用的工具；不执行原生编译任务。完成后再执行离线构建。联网解析仍会执行依赖代码，不能视为网络隔离；本入口同样限制本机文件、钥匙串和环境凭据访问。缓存文件与校验值不证明依赖来源安全，仍需审核原生依赖。

Gradle 分发包按上游 SHA-256 校验后重新解压，不执行本机已有的解压分发目录。Expo 使用锁定包中的本地模板生成新的 Android 工程；脚本检查模板、移除全部签名配置与模板测试密钥，再执行离线 `assembleRelease`。测试和 Metro 的依赖检查仍生效。生成目录仅在临时工作区中修改，项目的应用标识、原生权限和钱包功能配置保持原样。

编译结束后检查源码快照一致性并记录未签名 APK 的 SHA-256。另一临时沙箱仅接收 APK、标准签名工具和新生成的测试密钥，不接收项目源码、npm 依赖、Gradle 缓存或发行凭据。签名工具版本与校验值固定于 `native-build-policy.json`。这个步骤检查 APK 尚未签名，进行 16 KB 页对齐，签名后重新验证签名及对齐。[Android 签名工具说明](https://developer.android.com/tools/apksigner)

输出目录：`exports/native-review/<运行标识>/`，包含未签名 APK、测试签名 APK、源码清单、构建日志、签名证明和校验结果。编译与签名临时目录均在结束后删除；测试私钥和密码不写入输出或命令行参数。测试签名不是正式发行证书，每次运行证书不同，无法覆盖正式安装或其他证书签名的测试安装。不要为了安装测试包而卸载存有资产且尚未妥善备份的钱包。

仅对已经核对内容和 SHA-256 的未签名 APK 单独执行测试签名：

```bash
npm run sign:android:test -- /absolute/path/unsigned.apk VERIFIED_SHA256 /absolute/path/test-signed.apk
```

此入口始终生成临时测试密钥，不接受生产密钥。真实发行应使用独立受控的签名机器或签名服务，只接收已审核的 APK 与预期校验值，并使用自己的发行凭据。不要在签名作业内运行项目构建脚本、npm、Gradle 或配置插件。[Gradle 分发包校验说明](https://docs.gradle.org/current/userguide/gradle_wrapper.html#sec:verification)

Android Passkey 和已验证 App Links 依赖服务端对应用包名、签名证书指纹的关联配置。测试证书改变后，需要在自有测试服务中登记输出证明中的证书 SHA-256；否则这些功能可能被系统拒绝，即使钱包业务源码未变。本流程不修改线上域名关联或 WebAuthn 允许来源，也不据构建通过宣称服务端联调已通过。[Android Passkey 前置配置](https://developer.android.com/identity/credential-manager/prerequisites)

## iOS 与隔离边界

iOS 原生编译需要完整 Xcode；命令行工具不等于完整 Xcode。本流程不创建或上传 iOS 签名材料，没有执行 iOS 原生编译、归档或正式签名。具备完整环境后，应将 CocoaPods / 配置插件、关闭代码签名的编译与受控签名作业分开，限制发布凭据可见范围，并核验归档内容与对应源码。

macOS `sandbox-exec` 属于系统已有的隔离能力，后续系统可能改变支持情况；缺失时脚本停止。它限制文件、服务和网络访问，但不是完整虚拟机：允许系统运行时读取，Gradle 的本地通信仍可连接回环地址；系统或工具链漏洞、资源耗尽，以及不符合常见存放方式的秘密仍需要进一步防护。对不可信代码或正式发行，优先使用无秘密的独立构建机器 / 虚拟机，再单独签名。

签名、校验值、测试和构建隔离都不证明安装包没有恶意逻辑。应用运行时的普通私钥保护、交易确认、后端权限校验、真实设备验证及第三方材料授权仍需继续审查。
