# 网络切换与发现页（第一阶段）

## 范围与交互

当前实现 Vaulta 主网和 Jungle4 测试网。默认仅显示 Vaulta 主网，Jungle4 测试网需用户主动勾选。钱包列表左侧“＋”关闭列表并进入独立的网络显示设置页；切到“测试网”勾选 Jungle4 后，其图标才加入侧栏。取消勾选会隐藏入口，不删除钱包、历史或收藏。默认主网始终保留。

网络显示选择独立保存在 `eos3.networkVisibility.v1`，勾选本身不改变当前网络或账户。取消勾选当前正在使用的测试网时，恢复主网显示；启动也会在网络显示设置和钱包会话都恢复完成后应用该规则。读取失败不会覆写未知的原有偏好或强制切网，页面提供重试；保存成功后才更新勾选状态。

资产、发现、搜索及浏览器标签页的网络入口打开独立的网络选择页面，仅列出已启用的网络，共用 WalletContext 的 `chainId`。未启用测试网时，普通选择器也不显示测试网标签；设置页始终提供主网和测试网分类以便勾选。普通页面的分类标签仅筛选可选网络，点击具体网络才切换。钱包列表通过左侧图标直接切网，右侧网络标题为普通文本；左下角宫格打开“管理钱包 / 添加钱包”菜单。添加钱包从已启用网络中选网，再进入创建/导入选择；选网页的“＋”也可进入网络显示设置。网络选择不叠加在钱包列表上。账户、钱包、节点及资产沿用现有按网络隔离的逻辑，返回网络时恢复该网络的账户。

发现页立即按当前网络筛选横幅、推广、应用及模块；搜索使用同一目录规则。后台未配置 Jungle4 时显示空态。默认目录和未标记网络的旧目录仅属于 Vaulta，不会作为测试网的回退内容。

切网立即隐藏并结束旧 DApp 会话、最小化入口和待处理 ESR。尚未完成的风险确认、历史读取及打开请求均检查网络和请求代次，不能把旧网络结果带入新网络。收藏、历史、缩略图使用网络与 URL 的组合定位；清空仅作用于当前网络。原有未标记网络的记录保留为“未归类”，明确归属后才进入对应网络；若目标网络已有同 URL 的记录，保留原始副本，界面不重复提供归属按钮。

## 前端目录协议

运营后台在另一个项目，本阶段未改动。请求仍为只读公开接口，但新增能力标记：

```text
GET /api/app-content?discoveryNetworks=1
```

当前后台可忽略参数并返回原目录，前端按旧目录仅属于 Vaulta 的规则处理。后续后台上线网络配置时，必须只向携带该参数的客户端返回包含测试网部署的完整目录；不携带参数的旧客户端继续收到主网目录。这样旧客户端不会把测试应用当作主网应用。

保留 `schemaVersion: 1`，在现有条目结构中扩展可选字段：

| 字段 | 规则 |
| --- | --- |
| `networkIds` | 支持的网络 ID 数组（目前 `vaulta` / `jungle4`）；空数组表示不在任何网络展示。普通条目缺失时仅属于 Vaulta。 |
| 项目的 `networkUrls` | 网络 ID 到部署网址的映射。存在时仅使用明确配置的网址，缺少目标网络时隐藏该项目，绝不回退 `appUrl`。仍受 `networkIds` 限制。 |
| 模块子项的 `networkIds` | 缺失时继承所属模块的网络范围；明确配置时仍需父模块在该网络可见。 |

同一个应用可配置两个不同网址。例如以下为完整项目对象；示例域名不能作为真实应用发布：

```json
{
  "id": "example-app",
  "enabled": true,
  "sortOrder": 0,
  "name": "Example",
  "description": "Example application",
  "category": "Tools",
  "iconUrl": "",
  "featured": true,
  "appUrl": "https://main.example.com",
  "networkIds": ["vaulta", "jungle4"],
  "networkUrls": {
    "vaulta": "https://main.example.com",
    "jungle4": "https://test.example.com"
  }
}
```

模块通过现有 `projectId` 引用项目时，使用所选网络解析后的网址。横幅、推广和不引用项目的模块子项仍使用自己的 `url`；主网、测试网网址不同时应配置两个具有独立 ID 和对应 `networkIds` 的条目。空模块列表保持为空，不恢复旧主网模块。

网络 ID、重复范围、部署网址均经过验证，原有协议、长度、数量和网址安全校验继续生效。未知网络 ID 会拒绝本次目录更新并沿用已验证内容，因此后台不能向当前客户端发布尚未支持的网络 ID。

## 请求和缓存

保留一份经验证的完整目录，在渲染时同步派生网络视图。无需为每次切网重新发起目录请求，旧网络请求也不会覆盖当前网络的筛选结果。后台接口未来若改为“每次仅返回一个网络”，需要同时改造请求键、缓存键和取消机制，不能直接套用此实现。

新版缓存键为 `eos3.content.networks.v1:<API_BASE>`，与旧版主网缓存隔离；不改写旧缓存。仅在新版缓存不存在时，读取并按相同的大小、封装版本及内容规则验证 `eos3.content.v1:<API_BASE>` 旧缓存，使离线升级与重启继续保留已发布的主网目录及空列表。兼容读取不写入新版缓存，避免覆盖并发刷新所得的新目录；已有新版缓存（即使损坏）不会回退到更旧的目录。目录仍受 3 MiB 限制，现有刷新节流、取消、离线及发布空目录的规则保持有效。收藏和历史保留原存储键以保存用户数据，读写新增网络范围，并串行化修改以避免并发写入覆盖另一网络。

## 后续其他链

选择器从 `CHAINS` 注册表派生网络列表。`ChainId` 是网络标识，不应被当作所有公链协议相同的前提。当前交易、权限、签名和余额客户端仍为 Antelope。引入 EVM、BTC 等协议时应先增加链族与客户端适配层，并覆盖地址、资产标识、权限和签名协议，再登记可用网络；本阶段没有伪装成已支持这些公链。

## 验证

相关测试覆盖网络选择、主网旧目录兼容、网络网址独占解析、模块继承、搜索和发现同步切换、缓存兼容、收藏历史并发隔离，以及切网后的会话和延迟请求取消。原生验证证据和运行日志保存在本地 `exports/network-discovery/`，不包含密钥。
