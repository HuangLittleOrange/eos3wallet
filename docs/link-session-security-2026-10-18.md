# Anchor Link 会话撤销修复与验证

日期：2026-10-18。范围：钱包主工作区的 Anchor Link 会话列表并发写入，以及已接收推送在撤销后的生命周期。原有未提交修复继续保留；未生成、签名或发布安装包。

## 缺陷与影响

### 会话撤销被旧列表覆盖

`src/dapp/linkSessions.ts` 的新增和撤销原先分别读取整个 AsyncStorage 列表，再覆盖保存。已有 A 时，撤销 A 和建立 B 并发读取 `[A]`，可能依次写入 `[]` 和 `[A,B]`，从而恢复 A 的推送准入；两个撤销或新增也可能丢失彼此的修改。

现在所有列表变更进入同一个 Promise 队列，每项操作在前项结束后重新读取存储。失败继续返回给原调用者，且不会阻塞后续变更。会话输入在入队时复制，不受调用者之后修改的影响。

### 在途推送未随会话撤销失效

`LinkSessionProvider` 原先只在读取解密身份之前检查一次发送方名单。撤销发生在该异步等待期间时，旧处理仍会解密并交给 ESR；进入 ESR 解析、确认或解锁流程后，也没有来源会话撤销通知。

现在每个已准入发送方的授权生命周期对应一个 AbortSignal：

- 撤销意图立即使旧信号失效，存储变更仍按顺序执行并向调用者报告成败。
- 新消息准入等待已排队的列表变更；名单读取或身份读取完成后，旧信号不能重新变有效。
- 信号通过 `DappSessionContext` 和 `EsrRequestHost` 传递给 `useEsrFlow`。撤销关闭旧确认、丢弃迟到的解析或解锁结果，使已有签名路径的 `isCurrent` 失效。
- 新登录使用新生命周期，旧在途请求不会因重新登录恢复；确认回调另与其请求代次绑定，防止旧按钮作用于新请求。
- 无来源信号的独立扫码 ESR，以及其他发送方的合法请求，不受该撤销影响。
- 推送监听以连接代次检查前后台切换和卸载，旧连接不能在恢复前台后继续交付迟到消息。

这些问题影响本机 DApp 推送准入和请求取消，没有证据表明原缺陷能绕过交易确认、解锁或直接盗取资产。撤销不能收回已经发往对方的签名或已经广播的交易；修复阻断的是尚未越过交付边界的旧请求。

## 隔离与清理

本机 Docker 上下文指向 NAS，没有本机路径共享，因此使用任务专属 volume 传输脱敏源码，保留项目原来的 worker、非 root、只读根、cap-drop 和网络隔离参数。未挂载宿主 HOME、真实钱包、环境文件、凭据或发行签名文件，也未复用宿主 node_modules。

NAS 直接访问 Sigstore 超时后，使用临时的限定目标 CONNECT 通道，只允许 `registry.npmjs.org:443` 和 `tuf-repo-cdn.sigstore.dev:443`。未解密或修改 TLS，未更换注册表、信任根或关闭签名验证。只有依赖安装与来源验证阶段使用通道；项目代码与测试运行阶段网络为 none。传输和对照脚本保存在报告目录，任务卷与临时通道已移除；各轮 cleanup.json 均记录了任务卷移除成功。后续隔离验证需重新准备临时依赖。
