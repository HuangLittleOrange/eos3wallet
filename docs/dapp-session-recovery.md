# DApp 登录失效识别与恢复

钱包的本地连接授权与 DApp 后端的登录凭证是两个状态。重新打开浏览器后，本地授权可能已不存在，而网页仍从缓存显示已登录。钱包会在需要签名时要求连接确认，然后继续原请求；签名仍需单独确认。

## 实际请求失败后的识别

内置浏览器观察当前 HTTPS 站点的 fetch/XHR 响应，不改写原响应，不自动重试请求，也不读取或清除网页存储的凭证。请求与最终响应都必须同源。仅发送状态码与归一化错误码给原生侧；不发送响应内容、请求头或包含查询参数的网址。

只有 HTTP 401/403，且 JSON 的 `code`、`error.code` 或字符串 `error` 明确为 `SESSION_EXPIRED`、`SESSION_INVALID`、`INVALID_SESSION`（大小写不敏感），才会提示重新登录。

`TOKEN_EXPIRED`、`INVALID_TOKEN`、Bearer `error="invalid_token"` 只说明访问令牌被拒绝，DApp 可能自动刷新并重试，不能据此推断整个登录会话无法恢复。观察器不介入该刷新流程；只有后续服务端明确报告会话失效才提示，不通过等待若干秒或观察无关接口成功来猜测是否恢复。

普通 401/403、403 权限不足、断网、超时、429、5xx、链上权限错误、交易过期及错误文字中的“expired”都不能证明登录失效，不触发重新登录提示。fetch 响应副本最多读取 8 KiB；无法安全检查的响应保留原处理方式。

用户选择“重新登录”才撤销本地连接，并通知页面退出身份；随后由用户在 DApp 中重新点击登录/连接钱包。不会清空 DApp 的 localStorage、cookie 或其他业务数据，不会重放失败的交易。通知会去重；旧文档、旧钱包和新登录之前发出的响应不能使新连接失效，签名过程中不插入通知。身份未变的静默 `checkLogin()` 不改变会话代数；真正登录、退出和身份变化才改变。晚于新登录返回的旧静默检查结果会被丢弃，不能覆盖新身份。

钱包直接 POST 的 ESR 回调也使用相同的明确错误规则。没有钱包广播结果的请求，收到确定的登录拒绝后关闭旧请求并提示重新登录；网络失败或含义不明的 HTTP 错误仍按原回调错误处理。

如果钱包已成功广播交易，回调失败会返回包含交易号的 `callbackFailed` 结果，区分会话拒绝与普通通知失败。界面优先展示交易已提交及交易号，提示核对链上结果、不要重复提交；关闭旧请求的重签入口。回调会话拒绝只作为补充说明，不覆盖已上链结果。此规则也适用于回调断网和 HTTP 5xx。现有 ESR 身份证明超时检查继续独立生效，它不能证明 DApp 的持久会话已过期。

## 覆盖边界与验证

没有原始 DApp 报错，未宣称复现了原问题。上述 JSON 码是保守兼容规则，不能证明某个具体 DApp 实际使用这些码。HTTP 200 中的业务码、跨域 API、重定向登录页、WebSocket、自定义会话协议均不推断失效；需要有具体协议证据后单独适配。

回归测试覆盖明确失效响应、普通网络/权限/交易错误、原响应可读性、请求不重复发送、并发通知去重、旧响应隔离、用户确认前不撤销授权和 ESR 回调拒绝处理。

2026-10-22 复审修复新增覆盖：已广播交易遇到会话拒绝/断网/5xx 时保留交易号且不能从旧窗口重新签名；fetch 和 XHR 的令牌刷新成功不误报、刷新端明确会话失效仍提示；静默身份核对不吞掉分块响应、真正重新登录仍隔离旧响应、旧静默结果不能清除新身份。

## 本轮修复后的复审结果

- 上一轮三项问题均已修复，并有针对原触发条件的回归测试。
- 18 组 DApp 相关测试共 294 项通过；48 项工程检查通过；TypeScript 类型检查和差异空白检查通过。
- 用原审查的定向脚本再次验证：原生 `Response` / `ReadableStream` 中，令牌刷新成功不发送通知，静默核对期间的真实会话失效仍发送一次通知；交易成功广播后遇到失效回调，返回交易号，仅广播一次、回调一次。
- 复审上述交易结果、令牌刷新和请求代数处理路径，未发现新增的可操作问题。尚未进行真机与具体 DApp 后端联调，不能替代原故障的现场复现。
- 本轮没有新增依赖安装、构建包或审计工作副本；测试临时目录已由测试退出清理流程移除，源码、文档及原有未提交文件均保留。
