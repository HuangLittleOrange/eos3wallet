## ABI 信任来源

核心代币和已有 REX 操作继续使用本地固定编码。其他 ABI 必须得到至少两个不同内置 RPC 主机的一致回应；每个主机先核对链 ID，再读取指定合约 ABI，按标准二进制 ABI 编码计算哈希。远程运营节点目录、自定义节点和当前 RPC 返回的 ABI 不会因此自动取得信任。

交叉核验有请求和整体超时、失败节点替换、并发去重及十分钟内存缓存。拿不到一致结果时停止签名，不退回单节点校验。缓存按链及合约区分，代付意图检查失败时可重新核实。

普通交易、DApp 已序列化交易、ESR、代付意图核对及绑定交易 JSON 编码均使用同一套核验来源。普通交易保留原有节点构建流程；若该节点的编码与核实后的 ABI 不符，最终签名边界拒签。DApp 与 ESR 从核实后的 ABI 解码实际字节，展示真实收款人。

此方案抵御单个恶意 RPC，不是区块链轻客户端证明；两个受信主机串通、合约自身恶意、可信合约升级及既有委托风险仍需独立控制。

## 发布与安全边界

本次没有修改版本号、发布正式包或使用正式签名密钥。新增 Android 原生校验需要随新的完整 APK 发布，现有已安装的 1.0.9 不会自动获得修复。热更新保持关闭。iOS 没有新增原生模块，既有网页安装或商店跳转流程保留。

基线 Android 1.0.9（10）的 APK SHA-256 为 `e3dbc86c2b2bddb7c424dac70b379bad582e976bbadf97d4ecb61ee183cbc3a1`，正式证书 SHA-256 为 `760400107cc85ff86312473f854fe5fc5ff9e4237cdc280f07bfe4230628750a`，实际签名验证通过。包内没有 source map；Hermes 字节码、公开接口和合约信息仍可提取，不应当作秘密保护措施。

普通私钥在解锁和签名时仍会进入应用内存。已控制进程的恶意代码可以接触这些明文；客户端界面、生物识别成功判断或代码混淆不能解决这个运行时信任边界。现有密码加密、系统安全存储和认证门控继续保留。

依赖扫描返回的传播告警不能等同于可利用的钱包漏洞。现有 `elliptic` 与 `node-forge` 本地补丁校验通过；本次没有自动升级或降级依赖，扫描明细仍保留供后续维护。
