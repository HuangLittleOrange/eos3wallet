# 钱包逆向安全复查：资金与签名信任边界

日期：2026-10-18。本轮在前次三项修复的工作区上继续审查。按用户后续要求，结论优先讨论私钥、资产去向、签名和账户授权；缓存、资源消耗等探索记录不作为本报告的主要漏洞结论。

本轮确认两项问题：一项会影响后续收款去向，另一项会延长登录证明的重放窗口。随后按用户授权完成了这两项修复及回归验证；没有生成或发布新安装包。前次修复继续保留，用户原有修改未被覆盖。

## 修复实现

**A1 已修复：** 新增 `src/chain/importAccount.ts`，在保存私钥/助记词导入记录之前，要求至少两个不同内置 HTTPS RPC 主机返回一致的账户权限。自定义节点、当前选中的节点和远程节点目录不能自行取得信任。规范化比较权限树、阈值、公钥及权重、委托和等待项；兼容新旧公钥表示、Owner 的子权限和自定义权限。随后在本机核对所选权限确实包含本地公钥或其合法父权限中的公钥，不发送私钥或密码。

普通导入保留合法多签成员的导入能力，不把低于阈值的公钥成员误称为独占控制；界面提示用户确认预期恢复的账户。设备密钥导入也接入同一核验，并继续要求公钥直接满足 Active 权限的阈值，不放宽原有准入条件。

核验放在最终保存前且不缓存权限快照，失败时不保存钱包、不切换账户，保留原输入供重试。核验期间输入变化、切换链/节点、进入后台或退出页面会使旧流程失效；如果取消发生在加密存储期间，会清理这次新建的孤立密钥槽位。两个节点的核验共用从原 ABI 校验提取的 `trustedRpc.ts`：最多三个并发来源，单次响应含正文最多四秒，整轮最多十二秒；既有 ABI 核验测试保持通过。

**A2 已修复：** ESR v3 登录证明按本机时间生成不超过五分钟的有效期，先向下取整到秒以避免依赖库的秒级舍入把期限延长。节点时间只继续用于普通交易的 TAPOS，不再决定登录证明有效期。解析、签名前、签名后和签名交付前的既有检查同时拒绝过期、无效或超过五分钟窗口的证明，设备时钟明显回退后也不能交付旧证明。正常后台回调、页面跳转回调及 ESR v2 兼容路径继续保留；ESR v2 本身不提供 v3 的过期证明保证。

**验证与交付边界：** 新增真实导入页、账户发现、独立权限核验和收款页串联的离线回归：原恶意节点复现被拦截，正常私钥/助记词导入后收款二维码仍指向正确账户。覆盖 Hyperion 兜底、旧公钥、自定义权限、父权限、多签成员、设备密钥阈值、核验失败后重试及取消。登录回归确认节点自报 2099 年时，生成的证明仍在五分钟后失效，并拒绝签署或交付人为注入的长期证明。

最终验证：96 个 Jest 套件、939 项测试及 45 项工具测试全部通过；类型、源码和依赖检查通过。详细结果见 `exports/reverse-security-followup-2026-10-18/fix-final-full-tests.log`、`fix-static-checks.log` 和 `fix-verification.json`。原 `asset-paths.cjs`、`reproduce.cjs` 及其 JSON 结果是修复前证据，保留原样；修复后的判断应使用新增安全回归，而不是继续期待旧攻击脚本成功。

独立节点核验仍是信任锚方案，不是轻客户端证明，不能防止两个内置信任来源串通；公钥成员身份也不证明账户由用户独占控制。已保存的旧钱包账户名不会被自动修改。新增修复需重新打包安装后才会进入现有 App，本轮未进行真机安装、生产登录或链上资金交易。

## A1：恶意节点可污染导入账户，后续收款进入攻击者账户

**风险：高，具有明确触发条件。** 攻击者须控制导入时所用的 RPC 或返回账户候选的历史服务，用户还须接受界面显示的候选账户并完成导入。账户名在界面上可见，不是隐藏修改已确认转账的收款人。

EOS 账户名和公钥不是可以直接互相推导的关系。钱包本地正确解析私钥之后，还需要查询“这把公钥控制哪些账户”。修复前实现把查询结果直接提升为可签名的钱包身份：

1. `src/crypto/keys.ts:161` 的 `findAccountsByKey` 直接接受 `get_accounts_by_authorizers` 的 `account_name` / `permission_name`；Hyperion 兜底也直接接受 `account_names`。
2. `src/screens/ImportSecretScreen.tsx:123` 使用这些候选，并在第 133 行默认选中第一项。
3. 第 145 行开始的 `saveWallet` 验证的是本机主密码，随后保存“候选账户名 + 本地派生公钥”。没有在这一步独立验证该账户的实际链上权限是否包含并支持这把钥匙。
4. `src/screens/ReceiveScreen.tsx:35`、第 54 行起直接用选中的账户名生成收款码。

**已完成的离线复现：** 生成无资金测试密钥；模拟节点谎报该密钥对应 `attacker@active`，同时测试设定中的攻击者账户实际由另一把钥匙控制。执行真实导入页的解析、查找、输入测试主密码和保存流程，再挂载真实收款页。导入显示成功，保存的账户名及两个收款二维码的值均为 `attacker`；整个导入流程仅调用一次账户反查，没有独立账户/权限查询。系统存储、导航和原生界面由内存适配器替代，未读取或写入真实钱包。

复现脚本：`exports/reverse-security-followup-2026-10-18/asset-paths.cjs`；断言结果：`asset-paths.json`。

这条路径不需要窃取私钥，也不会在导入时转走旧账户余额。风险在于，用户相信钱包提供的“本人收款账户”，后续向这个收款码充值，资金会进入攻击者控制的账户。新加的签名前 ABI 核验处理的是交易字节与确认内容的对应关系，不能修复导入身份来源本身被污染的问题。

**修复方向：** 将反查结果视为候选，在正式保存前从独立的可信来源验证所选链、账户和权限；依据账户的真实 authority 校验公钥和权重，不能只检查返回的权限名字。未验证的记录不能伪装成已验证的可签名钱包。多签或间接授权应明确展示其能力，保留合法导入用途。还需让用户确认预期账户：任何第三方都可能把一个公开公钥加入自己的账户，所以“链上包含该公钥”也不等于证明这是用户想恢复的账户或其独占控制的账户。

## A2：RPC 的虚假区块时间可把五分钟登录证明延长多年

**风险：中。** 攻击者须控制当前 RPC；用户仍须确认登录签名。此问题针对 ESR v3 身份证明，不是直接的转账签名绕过。

`src/dapp/esr.ts:132` 根据节点返回的 `head_block_time` 生成“区块时间 + 五分钟”的到期时间。身份请求跳过普通交易的时间范围检查；`assertIdentityNotExpired`（第 54 行）只拒绝已经到期的证明，没有限制到期时间距离当前设备时间的上界。

**已完成的离线复现：** 模拟节点返回正确链 ID、虚假区块时间 `2099-01-01T00:00:00`。真实 `parseEsr` 得到到期时间 `2099-01-01T00:05:00`；真实 `signAndCallback` 路径继续生成测试签名并发送给模拟回调。随后用依赖提供的真实 `IdentityProof.verify` 和测试账户 authority 验证，该证明在 `2098-01-01` 仍通过。签名适配器使用无资金测试私钥，所有网络均为进程内模拟。

复现脚本：`exports/reverse-security-followup-2026-10-18/reproduce.cjs`；结果见 `reproduction.json` 的 F1。

这证明客户端宣称的五分钟有效期可被单节点绕过，并且标准的离线证明验证器会接受这份长期凭证。如果接收网站没有额外的 nonce、一次性使用或有效期上限检查，泄露的证明可能被长期重放。本轮未审查这些网站的服务端，不能据此断言任何具体网站已经能够被冒名登录。

**修复方向：** 身份证明的有效期使用客户端认可的时间范围，在解析与发送签名两个边界均检查“尚未过期且不超过允许的最长窗口”；节点时间显著偏离时拒绝。交易的 TAPOS 引用与登录证明的有效期应分开处理。兼容 ESR v2 时，应明确它没有 v3 的同等过期保证。

## 检查结果与边界

复核了密钥生成/派生、密码加密存储、普通私钥与 Passkey 签名、DApp 连接和请求实例绑定、Sponsor 意图核对、绑定授权重建及导出剪贴板路径。当前范围内未复现出新的“不经用户确认导出私钥或转走已有余额”的攻击。已解锁的普通私钥会进入应用进程内存，这一既有边界不重复列为新漏洞。

初次复查重跑 6 个相关 Jest 套件，共 127 项测试，以及 45 项工具/构建策略测试，全部通过。相关范围为运行时隐私、签名内容、DApp 授权、Passkey 验签、vault 和绑定授权。原回归通过与新发现并不矛盾：A1 的不可信账户发现和 A2 的未来有效期上界未被原测试覆盖；原 ESR 测试甚至把节点时间设置为 2099 年，并期望得到相应的到期时间。修复阶段已修改该期望并补上上述安全回归。

没有进行真机注入、真实账户登录、私钥读取或主网交易；服务端和链上合约实现也未在本轮完成独立审计。原生模块和 UI 使用模拟适配器的地方已在各复现结果中标明。

所有提取文件和 Jest 缓存使用受控临时目录并在退出时清理，保留源码、复现脚本、报告、反汇编片段及既有发布包。没有新增依赖安装或构建缓存。
