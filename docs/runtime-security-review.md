# 运行时安全核查

核查日期：2026-10-11。范围为本仓库的钱包密钥保管、导入与导出、普通交易、Sponsor、DApp / ESR 和 Passkey 签名路径。修复保留钱包功能和现有加密记录格式，Expo 和锁定依赖不变。本文记录源码审查及自动化测试结果，不是独立安全审计或真机验收证明。

## 私钥经过哪些通道

| 通道 | 本次发现与处理 | 边界 |
| --- | --- | --- |
| 日志 | 在已检查的应用路径中，未发现主动记录私钥、助记词或解锁密码的调用。密钥解析失败统一返回不含原始解析错误的提示。真实私钥签名插件的模拟 RPC 测试监测日志输出。 | 不证明操作系统、原生模块、第三方依赖或以后加入的日志系统不会读取秘密。 |
| 网络 | 正常签名发送公钥、账户、交易字节或签名，没有发现应用主动发送钱包私钥。测试使用新生成、无资金的测试密钥，核对网络请求中不含私钥字符串、旧格式私钥或原始私钥字节的十六进制。 | 签名本身可以授予交易或其他权限，不能当成没有价值的公开数据。恶意运行时依赖仍可能读取已解锁的私钥。 |
| 剪贴板 | 仅明确点击导出复制时写入秘密。串行化异步写入，取消或退出时清理晚到的写入，写入失败不显示成功；退出导出、进入后台或 30 秒后尝试清除本应用写入的值。 | 系统拒绝访问、进程被强杀、剪贴板历史和跨设备同步都可能使清理不完整；不能撤回其他应用已经读取的内容。 |
| 本地存储 | 普通钱包私钥使用密码派生密钥进行 AES-GCM 加密，密文放入 SecureStore。没有发现把钱包私钥写入 AsyncStorage 或普通文件的应用路径。加解密、随机密钥生成及助记词派生后清理可控的临时字节缓冲区；原生派生结果超时后才返回也会清理。 | JS 字符串、原生内部副本和垃圾回收时间不可控，不能保证内存全部归零。 |

创建账户时的待完成密钥单独保存于 SecureStore，以便中断后恢复订单。这是操作系统保护的存储，不是普通明文文件，但该临时槽位没有额外的钱包密码加密层。订单、公钥、账户信息等公开元数据可以进入 AsyncStorage。生物识别快捷解锁所需材料使用 SecureStore 的认证保护；设备接收 Link 消息的频道密钥也在 SecureStore，和资金私钥用途不同。

## 已修复的签名与展示问题

- 签名确认显示当前链、实际授权账户及权限，Owner 权限单独提示。DApp 不再丢弃无效 action、默默改写授权或对混合权限回退为默认权限；请求声明的链必须与当前钱包匹配。
- 确认后的 action 在异步准备前复制。签名前检查 action 数量、顺序、合约、名称和授权；已知核心代币 `core.vaulta` / `eosio.token` 的 transfer 使用本地固定编码核对发送人、收款人、金额和备注，拒绝恶意 RPC ABI 把备注等字段替换为收款人。
- 已序列化的 DApp / ESR 请求，从实际待签的 action 字节生成确认内容，并检查解码后重新编码是否完整一致。拒绝页面未展示的 context-free action、交易扩展、延迟执行、空 action，以及已过期或超过十分钟的交易。
- Sponsor 中使用用户授权的业务 action 按确认顺序匹配，附加费用必须使用确认的账户和权限，不能偷偷提升为 Owner；收费合约、收款人和金额仍与报价核对。
- 普通转账、资源购买、权限修改、开户付款及资源修复，将异步解锁和签名绑定到当时确认的请求、钱包、账户、节点、链及权限。重复点击、替换确认、上下文改变、进入后台或卸载页面，会使旧签名流程失效。为兼容 Android 系统凭据 Activity，本应用发起的限时系统认证期间暂不因后台事件取消；认证结果只有在回到前台后才继续使用，五秒内未回前台则失败。DApp 请求实例也单独绑定，重复使用请求 ID 不能恢复旧授权。
- ESR 确认显示签名接收方。只接受不含账号密码、接收域名固定的 HTTPS 回调；后台提交明确使用 Expo 原生 fetch，禁用自动重定向和附带会话凭据。不对签名回调自动重试。
- Passkey 拼装链上签名前，核对 challenge 与待签摘要、仪式类型、RP ID、credential ID、用户在场和已验证标志，再验证签名与当前钱包公钥匹配。普通私钥解锁后也检查对应公钥。
- 文本签名提示明确说明第三方可能将签名用于登录或其他授权，避免把“钱包不直接广播”误认为“签名不会影响资金”。

## 仍需处理的边界

1. **剪贴板导出和内存中的明文。** 保留复制、导出、普通私钥签名和短时复用资源修复签名者，意味着秘密仍会短暂存在于应用内存或系统剪贴板。被控制的手机或运行时依赖可以绕过 UI 和存储加密。最直接的使用防护是不复制资金私钥、不在不可信设备导入资金钱包，并减少高权限密钥使用。
2. **其他合约、ABI 和既有委托。** 本地固定编码保护仅覆盖已知核心代币 transfer。其他 action 仍依赖节点提供的 ABI；字节完整匹配不能证明 ABI 来源或合约实现正确，也不能证明用户已经授予的 `eosio.code` 等委托安全。Sponsor 自己授权的附加 action 仍被保留，需要审查服务端与合约逻辑。任意第三方合约仍可能在用户确认的调用里执行危险操作。
3. **已经发送的请求。** 本地取消可以阻止后续签名或提交，不能撤回已经发出的签名、RPC 请求或已经上链的交易。
4. **原生认证与服务端关联。** 自动化测试使用模拟原生接口，没有完成 Android / iOS 真机的 Keychain、Keystore、剪贴板和 Passkey 验收。Passkey 的应用来源关联依赖系统凭据提供方和服务端关联配置，本轮没有新增独立的来源白名单或完成后端审计。
5. **依赖和发布包。** 安装与构建隔离不隔离应用运行时依赖；已有依赖告警的实际边界见 `dependency-security.md`。此前生成的 APK 不包含本轮运行时修复，需要重新编译后才能用于这些修复的真机测试。

## 验证方式

新增或扩展测试覆盖真实私钥插件的请求与副作用、恶意 RPC ABI、收款人替换、残余 action 字节、授权和 action 顺序变化、请求取消 / 重复 ID / 后台切换、剪贴板晚到写入与失败、派生密钥超时清理、Passkey assertion 不匹配及 ESR 回调策略。正常转账和现有钱包流程保留原有回归测试；测试没有使用真实用户私钥或发送主网交易。

最终测试数量及源码快照校验记录见本地审查产物的 `source-manifest.json`。Android / iOS JavaScript bundle 验证不等于原生编译或真机验收；此前 APK 的构建证明仅对应其构建时快照。
